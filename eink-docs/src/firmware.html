固件与通信

有些行为电路本身保证不了，只能靠固件去做；漏掉任何一条，都会在样板上表现成"硬件问题"。这一页写给写固件的人，也包括电脑端常驻程序和书库服务。

电源状态机

点下面的事件按钮走一遍状态。电流是电池侧估算值，推导见功耗页。插着 USB 时不进深睡，这是 F3 已选定的方案 C（D1）的行为。

    唤醒源与睡眠

    • 防唤醒循环（F6）：进深睡前逐个读 ext1 的六个脚（三个按键 GPIO5～7、电源键 GPIO1、GPIO16、GPIO15），全部为高才睡。某个脚一直为低（键卡住、INT 或 ALRT 没清），就把它从唤醒掩码里去掉并记录日志，不要硬睡。
    • 电源键（v4.26，v4.33 补充）：上电后第一件事把 GPIO4（PWR_HOLD）拉高并 gpio_hold_en(GPIO4)；电源键（GPIO1，按下为低）从上电开始数满 3 秒才算开机（上电到固件跑起来的约 0.3～0.5 秒也算在里面），满 3 秒立刻局刷一行"正在开机"，不然用户按着键看不到任何反应；提前松手就先 gpio_hold_dis(GPIO4) 再拉低 GPIO4 断电（v4.31：hold 开着时拉低不生效）；这 3 秒内随时可能断电，不写 NVS 和 TF 卡。开机后先读 U10 的电量，过低就刷"请充电"后直接关机，免得反复欠压重启（在这个方案里每次复位都会断电）。开机那次按压要先松手，之后再长按 3 秒才算关机，否则一直按着会刚开机又关掉。关机：全刷关机画面，等 EPD_BUSY（GPIO2）变低后发 SSD1677 深度睡眠命令（0x10），把 U10 的 MODE 写成 0xC0 让电量计睡眠（v4.43，关机电流少约 15µA；提前松手和低电量关机也要写），等松手，再 gpio_hold_dis 并拉低 GPIO4（按着键时 ON 被按键拉着，提前拉低也断不了电）。低电量时先刷"请充电"再同样关机。
    • 电源保持（v4.33）：每次进深睡前确认 GPIO4 的 hold 开着，漏了的话一睡就断电（样板上量深睡时 ON 约 2.6V）。插着 USB 且被电脑枚举时不深睡，保证电脑上一直有原生 USB 串口，可以直接烧录；只接充电头时照常睡。不要占用 GPIO19、GPIO20，也不要关掉 USB-Serial-JTAG，否则只能手动 BOOT + RESET 并按住电源键。软件重启前要确认 GPIO4 的保持能撑过复位（样板实测）。
    • 功放：进深睡前 CTRL 置低并 gpio_hold_en(GPIO48)，醒来后 gpio_hold_dis。
    • 屏：刷新完立刻让 SSD1677 进深睡（GxEPD2 的 hibernate()）。高压不能长时间开着。
    • PSRAM：深睡后内容丢失，醒来从 TF 卡重读当前章。
    • 插着 USB 不深睡：方便串口调试和自动下载，也让方案 C 的"插电常连"成立。

    唤醒后的执行顺序

    1. 读 U8 确定当前方向和模式。
    2. 读 GPIO9（是否插着 USB）。充电状态由 U10 的电量变化判断，充电灯由 TP4056 自己驱动，固件不用管。
    3. 读 U10 的 SOC 和 VCELL（插着 USB 时 SOC 也有效）；桌面模式下唤醒 U7 并触发一次单次测量，ESP32 浅睡 500ms 后读回 CO2、温度、湿度，再让 U7 睡下。这时 Wi-Fi 还没开、芯片未发热，3V3 上也没有 Wi-Fi 发射的大电流波动，读数最准。
    4. 桌面模式联网拉取或等待推送，局刷，决定下一次唤醒；阅读模式进浅睡等按键。

    翻页交互

    屏幕不带触摸，看小说时 90% 的操作是"下一页"，交互围着这一点设计。

    方式操作说明
    侧键竖拿时按键固定在右边，从上到下是菜单、上一页、下一页；下一页最靠下，右手拇指自然落在上面v4.5 起 3 个键、方向固定；v4.6 起竖拿时 Type-C 和天线在下方、按键在右。桌面模式机器转 180° 放，固件把画面转过来。左手用户在设置里打开"倒着拿"：画面转 180°，按键重新映射
    长按长按下一页连续翻页或跳下一章；长按上一页回到本章开头；长按菜单：阅读模式下开始或停止朗读，桌面模式下切换模式长按约 0.8 秒触发
    敲击手指在后壳轻敲两下，翻到下一页U8 的 Z 轴双击检测，经 INT2 接 GPIO8；设置项，默认关闭，不要敲屏幕
    蓝牙翻页器连接 BLE 键盘类的翻页戒指或遥控器纯固件，可选模式；保持连接时看书续航约减半

    预渲染下一页：当前页刷完后，立刻从 PSRAM 里已预读的本章数据解码好下一页，按键一按直接局刷，约 0.5 秒翻过去，感觉不到卡顿。

    固件约定

    对象固件必须做的事不做的后果
    U6开机读 VL 位（v4.27 起 U6 接电池，关机也走时；VL = 1 说明电池拔过或耗尽，显示"未对时"，等和电脑端通信再对时）；关 CLKOUT；睡前清 TF/AF时间错乱；多耗电；唤醒循环
    U8先读 0x0F = 0x11、0x70 = 0x28 确认型号；按 SC7A20H 规格书写寄存器，不套 ST 驱动，不写保留区（0x00～0x0B、0x40～0x5F）；中断改为低电平有效（0x25 H_LACTIVE = 1）；每次睡前按当前方向只开其他方向的中断；醒来发现配置丢失就重新初始化；播放音频时忽略运动中断。敲击按 0x38～0x3D 的 SC7A20H 定义配置，CLICK_SRC 低 4 位为 2 才算双击。敲击只认 Z 轴双击，以下情况忽略：桌面模式、平放、方向刚变化的 1 秒内、正在朗读唤醒循环；改坏出厂校准；喇叭振动误切模式；走路、放下设备时误翻页
    U7只用单次测量，两次间隔 5 秒～10 分钟；测完发 0x3650 进睡眠；超过 3 小时没测先发 0x29BC 预处理；不发 0xE000；阅读模式不更新，切回桌面后前几次读数不显示；插 USB 时温度读数加标记或补偿空闲多耗约 55µA；自校准跑偏、读数漂移；呼气和体温让读数偏高
    U9插 USB 时音量上限 −3dB（F8）；不播放时 CTRL 拉低；CTRL 高电平选的是右声道，I2S 数据放右声道或左右都发喇叭超功率；待机耗电
    SW1～SW6按下、松开都做 20～30ms 消抖；两次短按翻页至少间隔 200ms，间隔内的按压丢弃（长按连续翻页不受限，由长按逻辑控制节奏）开关用旧后触点抖动，一次按压翻两页
    CARD1 TF 卡用完先把 CLK、CMD、D0 拉低，再拉高 GPIO10 关断卡电源；深睡前确认已关断。拉低 GPIO10 后等 ≥5ms 再初始化卡（缓启动，F18）；关电后要重新上电，等 ≥250ms卡被反灌供电，深睡电流多 100µA 以上
    Wi-Fi静态 IP，RTC 内存里缓存信道和 BSSID；失败时指数退避，电脑离线时拉取周期逐步拉长到 10 分钟每次连网 2～4 秒，续航减半
    U10 电量计上电写 MODE = 0x00 唤醒；没插 USB 时写 0x30 快速重估再写回 0x00（v4.43）；检查 UFG，需要时写入电池模型（F17）；ATHD 设 5%；睡前清 ALRT；关机前写 MODE = 0xC0 睡眠（v4.43）一直不测量、电量不变；开机电量停在关机时的值；电量不准；唤醒循环；关机电流多约 15µA
    电量显示用 U10 的 SOC；低电量门限用 U10 的 VCELL，在开 Wi-Fi 前、静置时读电量显示跳动；门限误判
    按键默认按键在右边（KEY1 菜单、KEY2 上一页、KEY3 下一页，和 EDA 接法一致，不用对调）；只有打开"倒着拿"时才把画面转 180° 并重新映射；桌面模式有提醒时短按菜单就是确认倒着拿时翻页方向反了；提醒没法确认
    屏桌面模式局刷 20～50 次或每小时全刷，阅读模式每 5～10 页全刷；切模式全刷；刷完 hibernate残影累积；高压长时间开着

    低电量策略

    电压取 U10 的 VCELL，在开 Wi-Fi 之前、静置状态下读。门限按 F7 调整过：v0.8 换薄电池后内阻更大，v0.9 换的 LDO 压差也更大，所以停止朗读提到 3.6V，停止联网提到 3.5V。拖动滑块看每个电压下哪些功能还开着。

    电池电压处理

    Claude Code 状态

    hooks 在指定事件发生时执行一条命令。hooks 只通知本机常驻程序，不直接连设备：设备可能在深睡，直连会超时，还会拖慢 Claude Code。常驻程序保存最新状态，按 F3 选定的方式交给设备。

    hook 事件设备显示声音
    UserPromptSubmit运行中—
    Notification等待确认提示音 A
    Stop完成提示音 B
    SessionEnd空闲—

    事件名已对照 Claude Code 文档。配置写在 ~/.claude/settings.json：

    {
  "hooks": {
    "Notification":     [{ "hooks": [{ "type": "command", "command": "python ~/epd/notify.py waiting" }] }],
    "Stop":             [{ "hooks": [{ "type": "command", "command": "python ~/epd/notify.py done" }] }],
    "UserPromptSubmit": [{ "hooks": [{ "type": "command", "command": "python ~/epd/notify.py running" }] }],
    "SessionEnd":       [{ "hooks": [{ "type": "command", "command": "python ~/epd/notify.py idle" }] }]
  }
}

    notify.py 只向 http://127.0.0.1:8765/event 发一个请求，超时 0.5 秒，失败也立刻退出。

    书库与朗读服务

    书由服务端整理、排版，排好的页面同步到 TF 卡，设备从卡上读。服务端最简单是并进电脑端的常驻程序：服务端做重活，设备只负责显示和播放。

    • 书库：存放 EPUB、TXT 等格式，统一转成纯文本并按章节拆分。只放自己合法获得的书或公版书。
    • 同步到 TF 卡：电脑端把排好版的页面图片按"书 / 章 / 页"的目录写到 TF 卡里，设备连上 Wi-Fi 时增量同步，也可以把卡插到电脑上直接拷。
    • 排版渲染：按 480×800 直接排版并渲染成 1 位黑白图片，字体、字号、行距都在服务端调。
    • 朗读：电脑端调用阿里云语音合成，把章节转成 MP3。可以提前合成好一起同步到卡上，没网时也能听；在线时也可以流式播放。按阿里云的条款和计费使用。
    • 进度：记录每本书读到哪一页、朗读到哪里，换设备也能接着读。
    • 设备端：翻页直接从 TF 卡读页面图片，不需要联网；进入阅读模式时把当前章预读进 PSRAM，读卡期间才打开卡电源。阅读进度写在卡上，联网时再同步回电脑。
    • 离开家：只看卡上已同步的书，不需要把服务端暴露到外网。
