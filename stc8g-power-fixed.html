电源板原理图（修正版）

USB-C → TP4056 充电 → 电源路径（D1 + Q1）→ VSYS → STC8G 软开关 → RT9080 → 3.3V 给 ESP32-S3；STC8G 和 ESP32 之间走串口。橙色圆圈编号对应下面的改动清单。

改动清单

#原图问题修改
1电源路径接反：Q1 串在 USB 支路上，D1、Q1 被连线短接，电池直接挂在 VSYS 上（USB 经 D1 绕过 TP4056 直接给电池充电），VSYS 和 USB_5V 也连在了一起（电池电压会倒灌到 VBUS）USB 只经 D1 供 VSYS；Q1 改到电池和 VSYS 之间：D=VBAT、S=VSYS、G=VBUS。插 USB 时 G=5V、S≈4.6V，Q1 关断；拔掉后 G 被 R4+R5 拉到 0V，Q1 导通，电池供 VSYS。删掉 VSYS–USB_5V 的连线，删掉两颗 R_PD
2TP4056 引脚错：BAT 标成 NC，VCC 脚接到电池，PROG 和 GND 短在一起，TEMP 没画，3 脚和 6 脚各出现两次按 1 TEMP / 2 PROG / 3 GND / 4 VCC / 5 BAT / 6 STDBY / 7 CHRG / 8 CE 重画：BAT 接 VBAT，PROG 经 R3 2k 到地（600mA），TEMP 接地，CE 接 VCC，VCC 补一颗 C1 10µF
3VBUS 检测：MCU 脚接在 5V 原值上，R5/R6 分压中点悬空MCU 脚改接分压中点（5V → 3.33V，C4 滤波），并换到 P3.3/INT1，插 USB 能唤醒 MCU
4按键 SW1 接 VSYS，IO 默认带上拉，按下去读到的还是高电平，检测不到SW1 改接 GND，用内部上拉，低电平有效；换到 P3.2/INT0，掉电模式下按键能唤醒
5LED 阴极只连了网络标签，没有接地；而且两颗 LED 占着 STC 的串口脚LED 改由 TP4056 直接驱动：VBUS → 1k → LED → CHRG / STDBY，充电中红灯亮、充满绿灯亮，不用单片机管，空出 P3.0 / P3.1 给串口
6U3 / C5 / C6 画了两份（位号重复）只保留一份；EN 用 R8 100k 下拉；输出电容加大到 22µF + 100nF（ESP32-S3 开 Wi-Fi 有电流尖峰）
7没有烧录口，STC8G 程序下载不进去加 J2（VCC / RXD / TXD / GND，2.54mm 4P）
8U1 引脚名和脚号对不上（6 脚写成 P3.0，8 脚写成 P3.1），VCC 画了两次按 SOP-8 实际脚位重画，引脚重新分配（见图右下表）
9STC8G 和 ESP32 之间没有通讯，ESP32 不知道充电状态、电池电压，也没法在断电前保存数据新加串口：STC 的 P3.0 / P3.1 设成开漏，R9 / R10 10k 上拉到 3V3，再经 R11 / R12 1k 接到 ESP32 的 IO17 / IO18。协议见下文
—位号不规范：R_PD 重复，R_CC1 和 R_CC2 标反了全部重新编号为 R1～R8、C1～C7

STC8G ↔ ESP32 通讯协议

串口 9600 8N1。每帧格式：A5 | CMD | LEN | DATA… | SUM，其中 SUM = CMD + LEN + 所有 DATA 字节之和，取低 8 位。

方向CMDLEN数据什么时候发
STC → ESP3201 状态4flags、电压 mV（高字节在前）、开机原因
flags：bit0 插着 USB，bit1 充电中，bit2 已充满，bit3 电量低
开机原因：1 按键，2 定时唤醒		状态一变就发，平时每秒发一次，收到查询也发
STC → ESP3202 按键11 = 短按开机状态下短按电源键
STC → ESP3203 关机请求11 = 用户长按，2 = 电量低开机状态下按住 3 秒，或者不插 USB 时电压低于 3.3V
ESP32 → STC81 查询状态0—ESP32 刚启动时
ESP32 → STC82 断电2几分钟后唤醒（高字节在前），0 = 只能按键开机收到关机请求、存完数据后；也可以由 ESP32 主动发（比如定时刷新完一次就断电）
  • 电压字段：报的是 STC 自己的 VCC。不插 USB 时约等于电池电压；插着 USB 时是 VSYS（约 4.6V），不代表电池电压。
  • 按键：关机状态下按住 1 秒开机；开机后短按发给 ESP32；按住 3 秒发关机请求，5 秒内收不到“断电”回复就强制断电；按住 8 秒直接断电，用于 ESP32 死机的情况。
  • 定时唤醒：STC 在掉电模式下每 15 秒醒一次计数，时间到了自动打开 3.3V，开机原因报 2。内部 32k 时钟误差大约 ±10%，30 分钟可能差两三分钟。
  • 低电量：不插 USB 时电压低于 3.3V 拒绝开机，开机状态下会发关机请求；低于 3.1V 直接断电。

代码

  • STC8G 固件（Keil C51）：stc8g-pmu/stc/pmu.c。STC-ISP 里选内部 IRC 22.1184MHz，并勾选“复位脚用作 I/O 口”（P5.4 要当 LDO_EN 用）。
  • ESP32 端（Arduino + PlatformIO）：stc8g-pmu/esp32/。PmuLink.h/.cpp 是通讯类，main.cpp 是示例，演示打印状态、短按、长按关机和定时唤醒。
  • 注意：STC 上电后、固件把引脚设成开漏之前那一小段时间里，P3.0 / P3.1 / P5.4 是带弱上拉的准双向口，LDO 可能被短暂打开几毫秒。如果在意，可以把 R8 从 100k 改成 10k，让 EN 下拉更强。

还要确认的几点

  • D1 反向漏电：不插 USB 时 D1 上一直有约 4V 反压，漏电经 R4+R5 流到地，等于电池上一直挂着一点负载。SS34 是 3A 普通肖特基，漏电偏大。如果在意待机时间，换成 RB168MM-40 这类低漏电管（1A，只给负载供电够用）。
  • RT9080 压差：600mA 时约 0.3V，电池降到 3.6V 左右 3.3V 就会跟着往下掉，ESP32 开 Wi-Fi 时可能掉电复位。续航要用到电池电量末段的话，考虑换成升降压方案。
  • 电池保护：图上没有过放和短路保护，要用带保护板的电芯，或者自己加 DW01 + 8205。
  • TP4056 散热：充电刚开始时功耗约 (5 − 3.7) × 0.6 ≈ 0.8W，底部焊盘要接大面积地铜。
  • 烧录：STC 要冷启动才能进 ISP。烧录时先拔掉电池，再由下载器经 J2 的 VCC 脚供电，下载器选 3.3V 电平。这时 ESP32 没上电，串口线上的 R11、R12（1k）会限制流进 ESP32 IO 的电流。
